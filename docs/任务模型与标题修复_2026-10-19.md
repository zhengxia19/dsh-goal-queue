# 任务模型与标题生成修复

日期：2026-10-19，时区 Asia/Shanghai。目标：Windows DPH / DeepSeek Harness Desktop V0.2.1-rc.2。

## 已实施

- 任务新增可选 `modelSelection={provider,model,reasoningEffort?}`，与活动占用、Session ID 和任务字段一起使用原有 revision CAS 保存。旧 version=1、activeId、空标题保持兼容；非法模型数据拒绝读取。
- 添加/编辑表单从官方模型目录列出模型与有效推理档位；默认保存完整快照。明确选择跟随默认或旧任务缺失时，在派发前解析并持久化配置。目录读取失败不可保存；模型不可用或档位失效停止派发。
- 创建 Session 后通过官方 `selectModel()` 应用配置，核对返回值与同一 Session 的 `modelSelection.next`；设置结果未知、不匹配或连接切换均禁止提交任务。标题请求后再次确认配置没有被手动改变。
- 标题请求使用同一 provider/model/reasoningEffort；Host 核验命令载荷与原生 model/selection 记录一致。不提供工具和任务 Session ID，不向 inbox 追加普通提示词。
- 移除固定 128 tokens，沿用 `llm.prepareCall()` 解析的 Host/模型预算。保留 8–80 Unicode 码点的最终标题上限。标题只接受显式 stop 结束和有效文本，不使用缺失结束事件或工具调用作为标题。
- 标题失败记录 finish、可用错误码、耗时和供应方实际输出/推理 token 数；未知值明确标记。不上报上游原始错误文本或题词；不自动重试或降档。标题失败不重发执行任务。
- 发现/恢复原 Session 不重新选择模型；保留无自动续跑、Session 去重、并发上限、异常阻断和原生完成判据。

## 官方接口限制与预算评估

`selectModel()` 会同时异步更新 Host 默认模型，不能宣称纯 Session 局部配置。界面明确提示这一行为；未使用内部 API、Desktop 补丁或“改全局再恢复”的竞态方案。

标题长度不等于生成 token 数，推理模型可能先消耗预算再产生标题。固定 128 tokens 对不同模型和推理档位不可靠。沿用已有模型预算可避免插件引入过小额度，代价是高档推理可能更慢、更贵；不宣称特定预算已通过全部模型验收。任务执行沿用 Host/模型预算，暂不新增最长 token 控件，单次响应上限也不等于整个 Goal 总预算。
