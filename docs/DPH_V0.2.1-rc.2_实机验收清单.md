# T06｜DPH Desktop V0.2.1-rc.2 真实环境独立验收清单

> **状态：待执行。** 下列项目仅为真实环境验收规程，并非已执行的报告。所有验收须使用 Windows 上实际运行的 DPH Desktop 客户端；不能用模拟测试或 GitHub Actions 代替。

## 前提与边界

- **独立验收人**和实现人分离；验收前先核实 GitHub 仓库 commit、`package.json` 版本、`node -v`、桌面程序完整版本、实际使用的 Desktop Profile 路径。
- 使用两个隔离测试 Workspace（含中文路径一个），全部操作只对测试文件生效。备份已有 Profile，并确认使用的插件管理入口支持恢复/卸载。
- 桌面插件安装可能依赖本地 DSH Profile；**不能假设** `dsh plugin --profile desktop add <目录>` 一定作用于实际 DPH Desktop。先检查 `dsh plugin --help` 和桌面发行版的安装规则。
- 不要以真实项目、生产数据或具破坏性的 `/goal` 作为测试题词。目标模式选简单的、能在测试目录内生成可人工检查文件的任务。
- 不在两个连接到同一 Host 的客户端同时开启队列：本版**不提供跨客户端分布式锁**。

## 原子验收任务（每项保存证据后才能勾选）

- [ ] **A01 环境与版本**：记录 Windows / DPH/Desktop / DSH Runtime 版本、测试 commit SHA、Host 配置备份与安装路径。确认实际 Client 加载插件版本，不是另一套 DSH Profile。
- [ ] **A02 安装和界面**：用发行版认可的入口安装插件并重启；侧边栏显示“任务队列”，管理面板可打开/关闭；无 JS/Cordis/Slot 注册错误。
- [ ] **A03 基础编辑与手工排序**：在两个已登记 Workspace 添加 3 个任务，编辑标题/说明，修改目标模式，上移/下移。未启动时不应创建 Session。
- [ ] **A04 串行 Workspace 隔离**：手工启动后，每个任务仅在指定 Workspace 新建一个 Session；上一任务未满足完成条件前第二任务不启动。保留对应 Session ID。
- [ ] **A05 原生 Goal 完成**：Goal `/goal` 成功匹配且对应投影 `goal.id`、`phase=complete`、Session 空闲后，才派发下一项；“文本声称已完成”不构成完成证据。
- [ ] **A06 Goal 阻塞**：制造安全的 Goal `paused` 或 `blocked` 状态。队列暂停，后续任务不启动；旧 Session ID 可检查。
- [ ] **A07 普通模式与暂停语义**：普通 Prompt 必须有运行→空闲的可观测证据；点击“暂停队列”不取消当前 Session，但不启动下一项。
- [ ] **A08 重启后禁止自动派发（空闲边界）**：Host 保存 `enabled=true`、`activeId=null`、含至少 1 个 `pending`（在隔离测试配置中精确构造），重启 Desktop。**必须 0 个新 Session**，队列处于待人工启动状态，原任务/顺序未丢失。
- [ ] **A09 断连恢复不自动派发**：先确保被重放的测试队列拥有上述空闲持久化状态，再断连/重连。连接恢复前后均不得自动创建 Session。
- [ ] **A10 运行中断**：测试任务运行时关闭桌面应用或切换 Host 连接。重新进入显示 `interrupted`、旧 Session 及异常原因；后续任务禁止自动执行。人工检查旧 Session。
- [ ] **A11 异常任务明确处置**：在 `interrupted/blocked/failed` 留有 `pending` 后继项时，“启动队列”不可用；确认旧 Session 状态后，分别验证“重新排队”（新 Session）与“人工跳过”（保留旧记录、标记 `skipped`）。
- [ ] **A12 配置加载失败**：用隔离 Host / 测试环境模拟 `settings.describe` 错误和无效 JSON/Schema；UI 必须显示实际故障，不得显示“队列为空”；所有编辑/派发操作禁用；重试读取恢复后原任务可见。
- [ ] **A13 写入失败/部分成功**：用受控模拟/故障代理验证 CAS 冲突、写入回包丢失、Session 创建成功但 ID 未保存等；无第二个任务派发，错误可定位。无法在真实环境可靠注入时明确标记“未实测”，不能伪造通过。
- [ ] **A14 卸载/回退**：按发行版插件管理流程卸载或禁用后，原桌面界面和其他工作区正常。不要自动删除用户任务和 Session 记录；保留恢复方案。
- [ ] **A15 独立复审**：由非实施人核对原始证据、异常路径、功能边界和安装/卸载；逐项标记通过/失败/未执行，仅全部必须项通过才能关闭 T06。

- [ ] V3-02：关闭面板再打开、反复点击「刷新运行任务」；不产生重复行和重复 Session。
- [ ] V3-03：将并发数从默认 1 提高到 2，确认两个队列新任务可同时处于运行；第三个等待。恢复默认 1 后不取消已有任务。
- [ ] V3-04：外部原有运行 Session 导入后占用并发名额；当已超过上限时，只暂停新增派发，不主动取消旧会话。
- [ ] V3-05：旧持久队列（version=1 / activeId）在新版中保留原 tasks、Session ID、历史；重新启动后必须保持暂停，运行中的原 Session 可重新关联。
- [ ] V3-06：已经停止但 Goal 尚未完成时，用户明确点击「激活旧 Goal」，复用同一 Session ID 且不新建 Session。普通任务不能自动重发。
- [ ] V3-07：新建任务的标题可以留空；普通任务有真实 DSH title 后同步显示。纯 /goal 任务不应为命名而新发普通 prompt。
- [ ] V3-08：断连、读取或 CAS 写入失败、Session 状态未知时禁止新派发，显示可解释的错误信息。
