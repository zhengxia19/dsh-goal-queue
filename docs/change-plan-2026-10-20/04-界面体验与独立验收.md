## T11 标题请求约束与诊断

- [x] **T11 源码与 CI 验证完成；前置：T10 验收通过。**

### 真实源码定位与问题

- `title-policy.ts:5,17–19` 对模型标题输入设 `MAX_TITLE_INPUT_CHARS=8000`，以 JavaScript `string.length` 判断，属于 UTF-16 代码单元限制；`QueueBoard.tsx:144–157` 的表单未提示该约束。
- `Coordinator.dispatch():176–187` 将标题异常写入单一 `detail`；`observeTask():52` 在完成时也更新 `detail`，可能覆盖失败诊断。
- `src/title-command.ts` 已通过原生 LLM 无工具请求并 `sessionTitle.rename()`；此任务不需要换 LLM 接口。

### 源码动作

| 类型 | 文件/对象 | 具体动作 |
|---|---|---|
| **修改** | `title-policy.ts:parseTitlePayload()` 或提示约束 | 明确标题输入上限的计数单位，UI 与 Host 的验证规则一致，避免“字符数”被误读；保留标题输出 8–80 Unicode **码点**上限。 |
| **修改** | `QueueBoard.tsx` 的标题勾选与任务表单 | 输入超过辅助标题限制时明确说明“任务仍可提交、标题辅助功能不能对过长题词使用”，提供关闭标题生成的路径，不隐式截断任务正文。 |
| **修改** | `Coordinator.dispatch()`、`observe-task.ts` 或适当的持久诊断字段 | 标题失败事件可与任务完成结果同时显示；不得把标题失败提升为任务执行失败，也不得在成功后默默抹掉故障原因。 |
| **必要时修改** | `Task`、`decode()`、`queueSchema` | 若为标题警告增加持久字段，要求旧数据兼容、Host schema roundtrip 和新增迁移测试。 |
| **新增测试** | `test/title-generation.test.ts`、`test/coordinator.test.ts` | 中文、emoji、长 Prompt、无模型、命令未注册、标题失败后任务完成、标题失败但任务不重复提交。 |
| **删除** | 无 | 不移除 `recordInput:false`、无工具调用、独立标题请求及输出硬截断。 |

### 验收

1. 8、24、80 的模型标题输出上限继续按 Unicode 码点执行；异常值在 UI 和 Host 同步拒绝。
2. 长任务说明不会被表单静默截断或删除；若勾选 AI 标题不符合辅助请求限制，必须有明确可处理提示。
3. 标题模型不可用、超时或生成结果非法时，原任务至多提交一次；失败原因在任务完成后仍可诊断，且不会错误显示“任务失败”。
4. 禁用 AI 标题时不发额外模型请求；纯 `/goal` 未勾选仍不伪造普通 Prompt。
5. 补充负向测试与全套测试、类型检查、构建成功。

## T12 任务列表与历史体验

- [x] **T12 源码与 CI 验证完成；前置：T11 验收通过。**

### 真实源码定位与问题

### 源码动作

| 类型 | 文件/对象 | 具体动作 |
|---|---|---|
| **修改** | `QueueBoard()` | 增加“待执行/活动”“异常待处理”“历史记录”筛选或折叠；为任务添加可查看旧 Attempt、原 Session ID 的入口，显示已知时间。 |
| **修改** | `Coordinator.open()` 或新增只读历史打开操作 | 支持打开特定旧 Attempt 的原 Session，不改变当前调度归属。 |
| **修改** | `styles.ts` | 历史项折叠、长 Prompt 溢出与窄屏处理，避免屏幕被大量历史信息挤满。 |
| **新增测试** | 相应 UI、Queue 状态和操作测试 | 多次重试、旧 Session 已丢失、导入 Session 无题词、100+ 历史记录、按筛选条件不影响任务顺序。 |
| **删除** | 无 | 不自动删除历史或归档清空任务。 |

### 验收

1. 用户可区分当前待执行、当前活动、异常需人工处理与历史已完成/已跳过记录；筛选不会重排真实派发 FIFO。
2. 同一任务 2 次重试后，能查看 3 次 Attempt 的 Session ID、已知时间和终态；打开旧 Session 不会发送任何新命令。
3. 未知时间/缺失旧 Session 显示“未知/不可访问”，不推测耗时或伪造链接。
4. 100+ 历史项时界面仍能操作，键盘及鼠标操作可用；不强制本轮实现分页后端和虚拟列表，除非性能实测证明有必要。
5. 组件/状态测试和完整 npm 测试、typecheck、build 成功，保存可读性截图与复审意见。

### 本次明确不做的体验改动

- **UX-06 自动停止已清空队列**：会改变“启用后新增任务是否立即执行”的既有含义，需要另行用户确认，当前保持现状并在 README 清楚解释。
- **UX-07 任意人工标题同步覆盖原生 Session 标题**：DSH title 具有 Host 所有权；若要实现双向同步，必须独立核验官方重命名行为和冲突策略，本计划不抢写原生标题。
