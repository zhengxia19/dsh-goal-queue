## 1. 用户需求和改造目标

用户希望在一个界面中跨 DSH 工作区安排普通 Prompt 与 `/goal`，按可调并发可靠派发；对外部已运行 Session 只观察；暂停后不误启动新任务；失败时保留证据并能安全恢复；重试仍能追溯旧执行；模型标题可选且不触发任务执行。系统必须在连接切换、写入失败和未知回包场景中**优先防重复派发**。

**目标排序**：正确性与不可重复执行 > 异常可恢复和会话可追溯 > 并发统计准确性 > 标题及列表体验。不得以 UI 优化先于执行安全修复。当前插件仍是 **Client 范围内的队列控制器**，不是跨 Host/Client 的分布式调度锁。

## 4. 必须遵循的架构原则

1. **调度授权与可见性分离**：Host 队列的 `enabled` 和 Client 的一次性人工 `armed` 不是同一状态；任何 error/reconnect 只能撤销授权，重新读取成功不能隐式恢复授权。
2. **提交边界可线性化**：必须定义“尚未提交/已越过可撤销边界/远端结果未知”三种状态。暂停只阻止未越过边界的新命令，不宣称取消已提交或可能提交的命令。不得通过检查一次布尔变量假装拥有原子取消能力。
3. **先确定再放行**：CAS claim、Session 创建和命令提交的未知结果不得重放；先记录 Session ID，提交不确定时停派并保存证据。
4. **恢复即执行**：`/goal resume` 与普通任务发送同等需要一次性互斥和持久证据；不能通过多次点击再次提交。
5. **任务历史与 Session 活动分离**：完成的任务不代表原 Session 永不再次运行；同一个 Session ID 不得作为两个未区分的任务重复计数。
6. **零静默数据损坏**：兼容旧 `version=1`、`activeId` 数据；迁移或读取失败显示错误，不自动初始化空队列。新字段须经 `queueSchema`、`decode()` 及旧记录用例共同验证。
7. **不得篡改原生 Goal 权威状态**：只有相同 Goal ID、`phase=complete` 且 Session idle 才表示 Goal 执行结束；普通模式仍依赖观测到的 running→idle。完成不等于代码验收通过。
8. **文档/真实兼容诚实分层**：模拟单测、类型检查、构建、Linux CI 成功，均不能替代 Windows DPH Desktop `0.2.1-rc.2` 安装/运行/卸载实机验收。

## 5. 变更范围及版本控制

- **必须实施**：T01–T09（执行安全、恢复、历史证据、正在运行 Session 计数、Goal 输入完整性）。
