## 安全性判断

- 自动发现不能触发 `sessions.create()` 或 `session.prompt()`；用户明确发起「激活旧 Goal」时才允许 `/goal resume`。
- `maxConcurrent` 是应用队列名额，而不是独占硬件或推理服务资源；不应将它宣传为操作系统总并发控制。
- 任务历史、原 Session ID、异常项目必须保留。不能通过重新创建 Session 假装恢复原任务。
- 普通任务的真正 `title` 从 Host Session 标题投影同步，不能由工作区名冒充模型标题。
- `goal.phase=complete` 与 Session 空闲共同决定 Goal 完成，普通任务需观察 running→idle；结束与代码验收不同。
- 多窗口分布式锁、原生纯 Goal 模型自动标题、真正 Windows Desktop E2E 均是未解决边界，不纳入当前完成声明。

## 实机验收追加项

在**两个隔离工作区**，使用 DPH Desktop V0.2.1-rc.2 测试：
1. 外部手工创建并运行 Session，打开队列，列表应出现且不会重复提交原 prompt。
2. 连续关闭/打开面板和手工点击刷新，不得创建重复记录。
3. 并发 1、并发 2、运行数超配降低到 1，不能强制取消老 Session，也不得超配再派发。
4. 运行中的旧队列 Session 在 DPH 重启后被识别并重新观察；当其已停止但 Goal 仍未完成，必须人工点击恢复。
5. 标题为空的普通任务由 DSH 原生标题服务决定真正模型标题（若 Host 未配置 LLM provider，仅显示回退，不应伪称由模型生成）。
6. 标题为空的纯 Goal 任务不应为了取名额外触发普通 prompt。
7. Host 配置读取失败、连接断开、CAS 冲突、不确定命令回包，都不能自动重发已有任务。
