# 模型标题生成扩展 — 实施与独立复审

日期：2026-10-19  
历史实施记录：下述默认模型/128-token 策略已由[任务模型与标题修复](任务模型与标题修复_2026-10-19.md)替代；原有独立复审不覆盖本次修复。
目标仓库：`zhengxia19/dsh-goal-queue`  
插件：`v0.3.1` 源码预览版；目标 DSH / DPH Desktop：`v0.2.1-rc.2`

## 实施范围

任务添加和编辑表单新增「由模型根据任务题词生成标题」勾选项（默认关闭），启用后出现「模型标题最长字符数」输入框，允许整数 8–80，默认 24。勾选后忽略人工标题输入，通过已有任务说明生成短标题。任务存储新增加可选的 `generateTitle` 与 `titleMaxChars`，旧记录缺省视为不启用；无需清空队列或重新创建 Session。

### 实现路径

1. 调度器在新 Session 建立后、执行任务前，以 DSH 专用命令平面发送 `/goal-queue-title <JSON>`，该指令不会附加执行用的普通 Prompt。
2. Host 端注册 `goal-queue-title`（`recordInput:false`），从当前 DSH 默认模型配置取得 provider/model，调用 `llm.prepareCall()` 执行**单独、无工具、不带 Task Session ID** 的辅助请求；输出最多 128 tokens。
3. Host 层对模型输出只取第一非空行、去除包裹标记、按 Unicode **码点**强制截断到设定字符数，并通过原生 `sessionTitle.rename(agent.session, title)` 产生持久的 Session 标题事件。
4. 队列 UI 从 DSH Session 目录中同步实际已接受的原生 `title`；未勾选时保持 DSH 标题行为不变。
5. 如果 Host 命令未注册、模型不可用、标题输出为空或接口出错，记录明确异常并**不会因此重发任务指令**；仍沿原有安全调度路径执行任务。

## 审查重点

| 检查 | 判据 |
|---|---|
| 任务不重复执行 | 标题生成绝不调用 `Session.prompt()` / `/goal`，不排队第二次任务执行 |
| 能作用于 Goal | 纯 `/goal` 任务勾选后亦可生成标题；不依赖首用户消息标题服务 |
| 模型输出限制 | 8–80 Unicode 码点；模型超长输出必须 Host 截断，而非只靠提示词 |
| 额外请求成本 | 仅用户勾选时触发；沿用 DSH 默认模型路由，可增加费用和开始延迟 |
| 权限与日志 | 没有额外 API key；模型标题请求不附任务 Session ID、不提供工具；命令输入标记 `recordInput:false` |
| 数据兼容 | `generateTitle` 与 `titleMaxChars` 均可选；旧任务默认不开启，任务顺序与 ID 不变 |
| 操作降级 | 标题失败不启动额外 Agent 工作；任务安全调度不受影响 |

## 自动化与实机验收边界

测试覆盖新增设置存取和旧记录解码、非法长度拒绝、Unicode 截断，以及 Mock Host 的实际 `prepareCall()` 请求，验证不提供工具或任务 Session ID、返回标题通过原生 `sessionTitle.rename()` 写入。

但测试桩不等于真实 Desktop 运行证据。**尚需 Windows DPH Desktop V0.2.1-rc.2 实机验收：**

- 本机默认模型 Host 服务可注入、命令可在新建 Session 使用；
- 普通模式和纯 Goal 模式分别生成标题，且没有新增普通执行回合；
- 调整最小/最大字符数，标题严格不超限；
- 停用标题勾选后依然完全复用原生标题逻辑；
- 故意制造标题接口异常，任务只派发一次，并正确留下诊断；
- 重启恢复、Session 去重、并发限制不回退。

**结论：必须以最新 GitHub CI 全绿和上述真实 Desktop 验收完成作为正式发布门槛。** 本次远端模拟测试成功只能认定源码阶段通过，不宣称已实现实机完整验收。
