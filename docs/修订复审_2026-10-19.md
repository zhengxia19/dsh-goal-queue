**目标版本：** DPH/DSH Desktop `V0.2.1-rc.2`；**插件版本：** `0.2.1`（源码预览）。

## 原始缺陷与复现

旧版只有保存的 `activeId != null` 才进入重启恢复。因此 `enabled=true`、`activeId=null`、有 `pending` 的队列会在重启/重连后自行提交新 Session。另一个缺口是 `next()` 会跨过 `interrupted/blocked/failed` 项寻找下一 `pending`，配置错误在前端被 `DEFAULT_SETTINGS` 伪装为空队列。

**红灯证据**：在修改源码前新增 `test/recovery-regression.test.ts`，前三个失败用例复现了重启误派发、重连误派发和未决异常未阻断；修改后同一用例应通过。旧版的独立类型检查、构建通过并不能发现这些逻辑缺陷。

## 实现边界与剩余风险

- **不是分布式锁**：仅能保证当前 Client 队列内部串行；无法阻止用户从其他窗口手动启动 Session。
- **不是后台任务调度器**：完全退出 Client 后不会继续派发；旧的 Host Goal 本身是否继续执行由 DSH 决定，队列不会替用户停止其执行。
- **不是自动代码验收**：`completed` 是 DSH 状态证据，不等于源码构建、测试或人工复审通过。
- **部分提交后 Session ID 可能缺失**：例如 Session 创建成功但对应 ID 的 Host 配置写入失败；队列必须标记中断/隔离并阻断后续任务，用户需从 DSH 对应 Workspace 查找旧 Session。
- **配置错误时不能重试派发**：读取故障提供显式重试按钮，不能把缺失状态默认为无任务。
- `tsdown` 旧 `external` 选项的弃用提醒属于非阻断工程警告；如构建/运行时正常，不把警告消除作为本轮 P0 安全修复的验收门槛。

## 独立复审重点

1. 无任何隐蔽的自动“resume/retry”通道；手工启用授权不入持久化。
2. Task 选择仍按用户上移/下移顺序；未决异常存在时 `next()` 拒绝执行。
3. `queue` 及 `activeId` 作为同一 CAS 写入；错误页显示真实错误、不会静默重置队列。
4. 在模拟 Host 读写故障、RPC 丢失、重连时，失败路径均无法创建第二个队列 Session。
5. 完成判据仍然严格区分 Goal 完成、普通 Session 运行结束、人工代码验收。
6. CI 完成后可关闭 T01–T05 的**自动化/源码门槛**；T06 必须另行实机验收。
